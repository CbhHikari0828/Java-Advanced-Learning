# chapter04_concurrent_collections 学习笔记

## HashMap 与 ConcurrentHashMap 的理解

`HashMap` 在多线程并发写入下不安全，可能出现数据丢失或内部结构异常，最终 `size()` 可能小于理论值。

`ConcurrentHashMap` 是为并发访问设计的 `Map`，多个线程可以安全地同时读写它。

`Map` 的 `size()` 统计的是不同 key 的数量；如果多个线程 `put` 相同 key，不会增加 `size()`，而是覆盖旧值。

## putIfAbsent 的理解

`putIfAbsent(key, value)` 把“检查 key 是否存在”和“放入 value”合成了一个原子操作。

如果 key 原来不存在，它会放入新值，并返回 `null`；如果 key 已经存在，它不会覆盖旧值，而是返回旧值。

它适合做并发场景下的“只初始化一次”：

```java
String oldValue = map.putIfAbsent("name", "thread-1 value");
```

相比下面这种写法：

```java
if (!map.containsKey("name")) {
    map.put("name", value);
}
```

`putIfAbsent` 更安全，因为 `containsKey` 和 `put` 分开写是两个动作，多线程下可能交叉执行。

## computeIfAbsent 的理解

`computeIfAbsent(key, mappingFunction)` 的意思是：如果 key 已经存在，就直接返回已有 value；如果 key 不存在，才执行后面的计算逻辑，并把计算结果放入 Map。

这里的计算逻辑就是 `key -> { ... return value; }` 这一段，它不是每个线程都一定会执行。

但是 `computeIfAbsent` 调用之后的普通代码，每个线程都会继续执行，例如：

```java
String value = map.computeIfAbsent("name", key -> {
    return "value for " + key;
});

System.out.println(Thread.currentThread().getName() + " get value=" + value);
```

在并发场景下，它适合做“按需初始化”：多个线程同时要同一个 key 的值时，只有一个线程真正负责计算，其他线程直接拿到最终结果。

## Collections.synchronizedMap 的理解

`Collections.synchronizedMap(new HashMap<>())` 可以把普通 `HashMap` 包装成同步 `Map`。

它会让单次 `put`、`get`、`size` 等方法调用具备同步保护，因此多个线程同时执行单次写入时，结果可以保持稳定。

但是，`synchronizedMap` 只保护单个方法调用，不会自动把多个方法组合成一个整体原子操作。

例如：

```java
if (!map.containsKey(key)) {
    map.put(key, value);
}
```

这里的 `containsKey` 和 `put` 是两次独立调用，中间仍然可能被其他线程插入。因此这类复合操作还需要额外同步，或者使用 `ConcurrentHashMap` 提供的 `putIfAbsent`、`computeIfAbsent` 这类原子组合方法。

## 并发遍历的理解

`HashMap` 在遍历过程中如果被其他线程修改，可能抛出 `ConcurrentModificationException`。

这个异常来自 fail-fast 机制：遍历器发现集合结构在遍历期间被修改，就快速失败。它不是多线程专属异常，单线程中边遍历边结构性修改也可能触发。

`ConcurrentHashMap` 支持并发遍历和修改，遍历时不会因为其他线程修改 Map 而直接失败。

但 `ConcurrentHashMap` 的遍历是弱一致性的：

```text
遍历过程中可能看到部分新数据，也可能看不到全部新数据。
它保证遍历过程安全，不保证看到某一时刻的完整快照。
```

## CopyOnWriteArrayList 的理解

`ArrayList` 在遍历过程中如果被其他线程结构性修改，可能抛出 `ConcurrentModificationException`。

`CopyOnWriteArrayList` 解决的是并发场景下 List 遍历安全的问题：一个线程遍历时，另一个线程可以修改 List，遍历线程不会因为结构变化而直接失败。

它的核心思想是“写时复制”：

```text
读的时候直接读当前数组。
写的时候复制一份新数组，在新数组上修改，然后替换旧数组引用。
```

所以遍历时看到的是开始遍历那一刻附近的旧数组快照，不一定能看到其他线程后来新增的数据。

本章 Demo 中，`CopyOnWriteArrayList` 最终 `size = 2000`，说明写入成功；但遍历只输出了 `0 ~ 800` 这些旧数据，说明遍历看到的是旧快照。

一句话总结：

```text
CopyOnWriteArrayList 牺牲写入性能，换来并发读取和遍历的安全，适合读多写少的场景。
```
