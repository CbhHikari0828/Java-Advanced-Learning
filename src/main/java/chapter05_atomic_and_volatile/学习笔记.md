# 第五章：原子类与 volatile

## 1. counter++ 为什么不安全

`counter++` 不是一个原子操作，它可以理解为三个步骤：

1. 读取 `counter`。
2. 计算 `counter + 1`。
3. 将结果写回 `counter`。

多个线程可能都读取到相同的旧值，再依次写回相同的新值，导致其中一次加一被覆盖。这就是并发丢失更新。

## 2. AtomicInteger

`AtomicInteger` 用于并发安全地操作 `int` 类型的共享值。

```java
private static final AtomicInteger counter = new AtomicInteger(0);

counter.incrementAndGet();
int value = counter.get();
```

- `counter++` 不是原子操作，并发下不安全。
- `incrementAndGet()` 是原子加一，并发下不会丢失更新。
- `final` 限制的是 `counter` 引用不能指向另一个 `AtomicInteger` 对象，不限制对象内部数值的变化。

常见原子类：

- `AtomicInteger`：原子操作 `int`。
- `AtomicLong`：原子操作 `long`。
- `AtomicBoolean`：原子操作 `boolean`。
- `AtomicReference<T>`：原子替换对象引用。

## 3. CAS

CAS 是 Compare And Set，意为“比较并设置”。

```java
counter.compareAndSet(expectedValue, newValue);
```

只有当前值等于期望值 `expectedValue` 时，才会更新为 `newValue` 并返回 `true`；否则不修改并返回 `false`。

并发场景中，CAS 失败说明读取旧值之后已经有其他线程修改了该值。此时需要重新读取最新值并重试：

```java
while (true) {
    int oldValue = counter.get();
    int newValue = oldValue + 1;

    if (counter.compareAndSet(oldValue, newValue)) {
        break;
    }
}
```

`AtomicInteger.incrementAndGet()` 的底层思路就是 CAS 重试。

## 4. volatile

`volatile` 保证共享变量的可见性：一个线程修改变量后，其他线程后续读取时能够看到该修改。

```java
private static volatile boolean running = true;
```

适合用作运行开关等简单状态通知。

`volatile` 不保证复合操作的原子性：

```java
private static volatile int counter = 0;
counter++;
```

即使每次读取都能看到最新的可见值，两个线程仍可能在写回前读到同一个旧值，最后相互覆盖。因此，`volatile` 不能替代 `AtomicInteger` 或 `synchronized` 来完成并发计数。

一句话：`volatile` 解决“看得见”，原子类和锁解决“改不乱”。

## 5. LongAdder

`LongAdder` 也能安全累加，但更适合高并发、频繁计数的场景，例如访问量、请求数和监控指标。

```java
private static final LongAdder counter = new LongAdder();

counter.increment();
long total = counter.sum();
```

- `AtomicInteger` / `AtomicLong`：适合需要精确读取当前值、CAS 更新单个状态的场景。
- `LongAdder`：适合大量线程频繁累加，目标是降低竞争、提高吞吐量。
- 两线程累加并得到正确结果，只能证明 `LongAdder` 不会丢失更新；要体现其性能优势，需要在更多线程、高频累加时与 `AtomicLong` 对比。
