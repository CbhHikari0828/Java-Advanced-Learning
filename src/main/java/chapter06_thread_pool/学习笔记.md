# 第六章：线程池

## 1. ExecutorService

线程池用于复用工作线程，避免每个任务都手动创建和销毁线程。

```java
ExecutorService pool = Executors.newFixedThreadPool(2);
pool.execute(task);
```

任务执行完成后，工作线程通常不会立即销毁，而是继续等待并执行任务队列中的下一个任务。

线程池线程是执行任务的线程，提交的 `Runnable` 或 `Callable` 才是任务，线程池把两者管理起来。

## 2. submit 与 Future

`execute()` 适合提交没有返回值的 `Runnable`。

```java
pool.execute(() -> System.out.println("running"));
```

`submit()` 可以提交 `Callable`，并返回 `Future`：

```java
Future<String> future = pool.submit(() -> "task result");
String result = future.get();
```

`Future.get()` 会等待任务完成并获取返回值。

## 3. 关闭线程池

```java
pool.shutdown();
```

`shutdown()` 不再接收新任务，但已经提交的任务会继续执行。

```java
pool.shutdownNow();
```

`shutdownNow()` 会尝试中断正在执行的任务，并返回还没有开始执行的队列任务。它不能强制杀死线程，任务必须正确处理中断。

`awaitTermination()` 只负责等待线程池彻底终止：

```java
boolean terminated = pool.awaitTermination(10, TimeUnit.SECONDS);
```

返回 `true` 表示规定时间内已终止，返回 `false` 表示等待超时。它本身不会关闭线程池。

## 4. ThreadPoolExecutor 的任务接收规则

以核心线程数 `2`、最大线程数 `4`、队列容量 `2` 为例：

1. 当前线程数小于核心线程数时，创建核心线程执行任务。
2. 核心线程已用完时，任务进入队列。
3. 队列已满但线程数未达到最大值时，创建非核心线程执行新任务。
4. 队列已满且线程数达到最大值时，执行拒绝策略。

任务队列通常保证排队顺序，但线程池整体不保证任务的执行顺序，因为多个工作线程可能并发执行任务。

## 5. 拒绝策略

当线程池和队列都满时，常见策略有：

- `AbortPolicy`：抛出 `RejectedExecutionException`。
- `CallerRunsPolicy`：让提交任务的线程自己执行任务，形成反向限流。
- `DiscardPolicy`：静默丢弃新任务。
- `DiscardOldestPolicy`：丢弃队列中最旧的任务，让新任务进入队列。

## 6. 定时任务

`ScheduledExecutorService` 可以延迟或周期执行任务：

```java
scheduler.schedule(task, 2, TimeUnit.SECONDS);
```

表示延迟 2 秒执行一次。

```java
scheduler.scheduleAtFixedRate(task, 0, 1, TimeUnit.SECONDS);
```

按照固定频率执行，关注任务的计划开始时间。

```java
scheduler.scheduleWithFixedDelay(task, 0, 1, TimeUnit.SECONDS);
```

上一次任务完成后，再等待 1 秒执行下一次，适合必须间隔一段时间的轮询任务。
