# 第七章：生产者消费者

## 1. BlockingQueue

生产者消费者模型中，生产者负责放入数据，消费者负责取出数据，中间通过共享队列传递数据。

`BlockingQueue` 是专门用于线程协作的阻塞队列：

```java
BlockingQueue<Integer> queue = new ArrayBlockingQueue<>(2);
```

- `put(value)`：队列满时阻塞生产者，直到队列出现空间。
- `take()`：队列空时阻塞消费者，直到队列出现数据。
- `ArrayBlockingQueue`：有界队列，容量创建后固定。
- 队列通常按照先进先出顺序取出元素。

生产者和消费者的输出顺序可能交错，这是线程调度造成的；但消费者取出的数据仍然遵循队列顺序。

## 2. offer 与 poll

不希望线程无限等待时，可以使用 `offer()` 和 `poll()`：

```java
boolean offered = queue.offer(value);
Integer value = queue.poll();
```

- `offer(value)`：放不进去时立即返回 `false`。
- `poll()`：取不到元素时立即返回 `null`。
- `offer(value, timeout, unit)`：最多等待指定时间，失败返回 `false`。
- `poll(timeout, unit)`：最多等待指定时间，取不到时返回 `null`。

对比：

```text
put / take       可能一直等待
offer / poll     可以立即返回或限定等待时间
```

## 3. 手写有界缓冲区

`ArrayDeque` 本身不是线程安全的。可以使用 `synchronized`、`wait()` 和 `notifyAll()` 手动实现一个有界缓冲区。

```java
while (queue.size() == capacity) {
    wait();
}
```

队列满时，生产者释放锁并等待。

```java
while (queue.isEmpty()) {
    wait();
}
```

队列空时，消费者释放锁并等待。

成功放入或取出数据后调用：

```java
notifyAll();
```

通知其他等待线程重新检查条件。

等待条件必须使用 `while`，不能使用 `if`，因为线程被唤醒后仍然需要重新确认条件是否成立。

## 4. notify 与 notifyAll

`synchronized` 对象只有一个等待集合，生产者和消费者都会在这个集合中等待。

- `notify()`：随机唤醒一个等待线程，可能唤醒一个条件仍不满足的线程。
- `notifyAll()`：唤醒所有等待线程，线程重新竞争锁并通过 `while` 检查条件。

在多个生产者、多个消费者共享同一个缓冲区时，通常使用 `notifyAll()` 更稳妥。

## 5. ReentrantLock 与 Condition 的联系

`ArrayBlockingQueue` 内部使用 `ReentrantLock` 和多个 `Condition` 管理等待线程。它可以分开维护：

```text
notEmpty -> 等待数据的消费者
notFull  -> 等待空间的生产者
```

因此放入数据后可以唤醒消费者，取出数据后可以唤醒生产者。`ReentrantLock` 的底层依赖 AQS，线程竞争锁时会进入 AQS 同步队列。

## 6. 结束标记

如果消费者一直调用 `take()`，没有新数据时会永久等待。可以放入一个特殊值作为结束标记，通知消费者停止循环。

```java
private static final int POISON_PILL = -1;
```

毒丸是应用层的结束协议，不是 `BlockingQueue` 的底层机制。多个消费者时通常需要为每个消费者准备一个结束标记。

## 一句话总结

生产者消费者模型的本质是：使用安全的共享缓冲区协调生产和消费，并在“满”和“空”两种状态下正确等待与唤醒。
